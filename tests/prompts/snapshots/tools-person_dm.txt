asks_answer: Answer an open ask of this person with an option id in `option`, or with `text`. Always a draft card: the answer goes out only when the person taps Send. An ask of another person is refused.
asks_answer_with_rule: Answer an open ask with a standing rule of its owner: the ask `id` and the `rule_id` from `rules_list`. Code answers only when the rule matches one of the ask's options; else the result is `answered: false`. Never use it to decide yourself.
asks_cancel_mine: Cancel an open ask that this person owns or asked, when they say it is no longer needed. Returns `cancelled: true` or `false`.
asks_create: Ask one teammate for a decision, an action, a review, or a reminder; they get a card. Then tell the requester whom you asked and what. `owner` is a person key from `people_list`; put the reason and a link in `question` or `proof`, and `options` when the answer is a choice. At most 3 per run.
asks_get: Read one ask by `id`: the question, its options, the recommended option, and the proof that the asker gave.
asks_list: List the open asks that this run can see; `owner` (a person key) limits the list to one person. One line per ask with its id, kind, question, owner, due time, and link.
brief_settings: Read or change this person's own morning brief: on or off, and the local time when it arrives. Change it only when the person asks, then confirm the new setting in one line. It cannot change the brief of another person.
calendar_list: List this person's calendar events between `from` and `to`: ISO times with a time zone, for example 2026-11-12T00:00:00+01:00, and `to` after `from`.
chatgpt_status: Check the ChatGPT sign-in that pays for this person's runs. Returns one status sentence that you can pass on. Use it when the person asks about their sign-in.
claims_take: Lock an item so that only one run handles it, for example an alert that arrives twice. `key` must be identical for each copy; use the format of a team rule if one gives it. Returns true when this run has the claim; false means that another run has it, so stop. A claim lasts 24 hours.
connectors_call: Call one tool of a connected outside service, with `connector`, `tool`, and `arguments` as `connectors_list` shows them. The arguments leave the team, so put no personal data in them; the call is refused after a personal read. A remote tool that sends outside becomes a draft card.
connectors_list: List the team's connected outside services and the tools that this run may call, with their input schemas. Call it before `connectors_call` for the exact names.
digest_snapshot: Read what needs this person now: their open asks, reviews, agent threads that wait for them (kind `your_move`), stuck work, work in progress, finished work, and service faults. Call it first for 'what needs me?'. It counts as a personal read.
drive_get: Read one of this person's own Drive files by `id` from `drive_search`.
drive_search: Search this person's own Drive files. For team documents, use `drive_shared_search`.
drive_shared_get: Read one file of the team's shared Drive by `id` from `drive_shared_search`.
drive_shared_search: Search the team's shared Drive, through the team's grant, not a person's own files. Returns one line per file with its id.
email_draft: Draft an email to `to`, with `subject` and `body`. The result is always a draft card in the DM of the person you act for; the mail goes out only when they tap Send.
github_assign_issue: Propose to assign an issue to a team member (`assignee`: a person key or GitHub login). Always a draft card: the assignment happens only when the person you act for taps Assign.
github_comment_issue: Propose a comment on an issue or pull request; `body` is the full comment. Always a draft card: the comment is posted only when the person you act for taps Send.
github_create_issue: File one issue in a configured repository. `signature` is a short phrase with no colon, quote, or backslash that stays the same for every report of one problem: when an open issue already has it, nothing is filed and the result lists the matches (use `force_new_reason` only for a different problem). A private repository files at once; a public repository or a label that starts agent work needs a draft. For outside text, code chooses automatic assignment to the default owner or an owner card. Report `assignment` and `assigned_to` from the result. You never choose an assignee for outside text.
github_get_issue: Read one issue by `repo` (owner/name from the run facts) and `number`: its body, labels, assignees, and the last 5 comments.
github_get_pull: Read one pull request by `repo` and `number`: its body, merge state, head commit, checks, reviews, and the last 5 comments. Use it to say whether a pull request is ready.
github_search_issues: Search issues and pull requests in the configured repositories. Pick one with `repo` (owner/name from the run facts); a `repo:`, `org:`, or `user:` qualifier in `query` is refused. Returns one line per item with its number, state, title, labels, assignees, and link.
lanes_get: Read one lane by `id`: its summary, links, and last 5 events.
lanes_mine: Same as `lanes_search`, limited to the lanes of the person you act for. Returns nothing in a run with no person.
lanes_search: Search the lanes that this run can see: agent or ticket work with a state (open = backlog, working, waiting_person, blocked, review, done, failed). Filter with `query`, `state`, `owner` (a person key), and `repo`. Returns counts by state and one line per lane with its id and link.
mail_get: Read one message of this person's own mail by `id` from `mail_search`.
mail_search: Search this person's own mail. `query` uses Gmail search syntax; returns one line per message with its id.
notes_propose: Propose a team note with `title` and `text`. The person you act for gets a card, and the note is saved only when they tap Keep; until then the result is pending, so say that the note waits for their approval.
notes_search: Search the team notes only. For anything else, use `search_all`.
people_get: Read one active team member by their `key`.
people_list: List the active team members: key, name, role, areas, and GitHub login. Use the key in `owner`, `person`, and `assignee` arguments.
rules_list: List the standing rules that answer asks without a person: the team's and those of the person you act for, each with its id, text, match, and answer. Use the id with `rules_remove_mine` or `asks_answer_with_rule`.
rules_remove_mine: Remove one of this person's standing rules by `id` from `rules_list`, when they ask. Asks that the rule answered come to them again. Returns `removed: true` or `false`.
search_all: Search everything this run can see, ranked by match and recency. Optional `kinds`: saved, decision, note, lane_summary, archive, slack, github, doc, lane, and mail (this person's mail, DM only). Read one result in full with `search_get` and its `source_ref`.
search_get: Read one search result in full by its `source_ref` from `search_all`. A long text comes in pages of 6,000 characters: pass `offset` to read on.
skills_get: Read the steps of one team skill by its name
slack_post_channel: Post in a configured team channel (`channel`: its id; `thread_ts` to answer in a thread). It becomes a draft card after a personal or private read.
slack_read_thread: Read the current Slack thread, or a thread in a configured channel: `channel` is the channel id and `thread_ts` the timestamp of its first message. Pass `offset` for more messages.
slack_send_dm: Send a Slack DM to one team member (`person`: a person key). For a question that needs an answer, use `asks_create` instead. It becomes a draft card after a personal or private read. At most 3 per run.
team_snapshot: Read the team's state for the team brief: what shipped, what is stuck, and what waits for whom. It holds team-visible data only, never a private lane or a private ask.
web_read_public_page: Read one public web page whose URL is in the run message, or the root page of that host. In a run from outside text, only the first URL of the message, once. Refused after this run read personal data.
work_start: Start work through a GitHub issue: file it in a configured repository, track it as a lane, and post a status message. With `assignee` (a person key or GitHub login) in a person's run, the result is a draft card, and the issue is filed and assigned only when the person taps Send. Without a person, code decides ticket ownership under the outside-text triage rules. A model assignment is refused with `deny` and the ticket link. `signature` works as in `github_create_issue`; once per run.
